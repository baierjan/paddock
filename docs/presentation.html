AI Show & Tell • Rootless Podman + libkrun
Welcome everyone. This is a quick walk-through of Paddock, a lightweight tool built to give autonomous AI coding CLIs (like opencode and gemini-cli) a real microVM boundary on Linux without heavyweight VM management.

The Virtualization Boundary

Why container namespaces fall short for autonomous agent execution

Shared Kernel

Standard Containers

  • Share the host Linux kernel
  • Namespace escape attack surface
  • Host networking & LAN exposure risks
  • UID/GID mapping friction on bind mounts
Heavyweight

Traditional VMs (QEMU)

  • Full hardware emulation overhead
  • Multi-second boot latency
  • High baseline RAM consumption
  • Clunky host filesystem sharing
Sweet Spot

MicroVMs (libkrun)

  • Hardware KVM virtualization boundary
  • Millisecond container-speed startup
  • Native virtio-fs host folder sharing
  • Runs under standard rootless Podman
We know why agents need shell execution, but running autonomous LLM commands on bare metal or shared namespaces is risky. Standard containers share the host kernel. Full QEMU VMs are too slow and bulky for an interactive CLI loop. MicroVMs via libkrun combine KVM hypervisor isolation with container-speed launch.

Architecture & Hardening Baseline

Defense-in-depth with zero background daemons

System-Wide Lockdown

  • Read-only rootfs: --read-only prevents system tampering
  • Zero capabilities: --cap-drop ALL & no-new-privileges
  • Hardened /tmp: in-memory tmpfs with noexec,nosuid,nodev
  • Network isolation: isolated network namespace via pasta
  • Resource caps: bounded RAM, vCPUs, and PIDs
  • Privilege drop: guest entrypoint drops root to unprivileged ai user via setpriv, then runs the command through a login shell so profile-defined environment is always set

Ergonomics: "Pristine Home"

  • No config-copying sync layers: avoids brittle intermediate caches and sync scripts
  • Empty image home: /home/ai is completely empty in the image; shell dotfiles live in /etc/bash.bashrc
  • Direct persistence: ~/.local/share/paddock/home binds directly to /home/ai for shell history and CLI auth
  • Workspace mount: host $PWD binds to /home/ai/sandbox
Paddock is pure Bash plus one Containerfile. Hardening is comprehensive: read-only rootfs, noexec tmpfs, dropped capabilities, and pasta networking. Crucially, the guest boots into an entrypoint that drops permissions to user ai using setpriv. For persistence, we avoid cache managers by keeping /home/ai empty in the image and directly bind-mounting local user state.

The paddock Command & Packaging

One entry point, one flag list

Everyday use

  • paddock run builds the image if needed, then launches the sandbox in the current folder
  • paddock run -w <folder> [command...] lands in a subfolder or runs a command directly; paths and arguments reach podman as clean argv
  • Unnamed runs allow concurrent sandboxes in separate project folders
  • sandbox_flags() is the single definition of every mount and security flag

Native OCI & Distribution

  • Baked-in LABEL run: the same flags live in the image metadata, so a plain launch also works without a checkout: 
    podman container runlabel run paddock:latest
  • openSUSE Tumbleweed: RPM spec in packaging/ packages the paddock CLI and pulls dependencies
  • Personal Overrides: Place a custom Containerfile in ~/.local/share/paddock/Containerfile; automatically inherits the hardened runtime label
Day to day you just use the paddock command. Run builds the image on first use and launches the sandbox in the current folder; with -w or a command it runs podman directly so paths and arguments arrive as clean argv. Both paths use one flag list, sandbox_flags(), which is also baked into the image as the run label, so podman container runlabel works as a nice extra without the repository. If you need custom compilers, you can override the Containerfile locally without modifying tracked git files.

Live Demo & Discussion

Verification Checkpoints

# 1. Launch sandbox in the current folder
paddock run

# 2. Verify microVM isolation inside guest
id                  # non-root user 'ai' (UID/GID 1000)
uname -r            # guest's own kernel (compare with host)
nproc; free -m      # capped vCPUs and RAM
ls /sys/class/net   # virtual NIC only, no host interfaces

# 3. Run an assistant in a project subfolder (opencode or gemini)
paddock run -w myproject opencode -c
